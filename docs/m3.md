# M3 — Potential Score

## Delivered

- `lib/domain/score/compute.ts`: deterministic `computeScore(inputs, config)`, used by the mock repository. No I/O, framework imports or internal clock. This follows the shared-domain location chosen in `backend-spec.md` rather than adding a second `lib/score` implementation.
- `config.ts`: preview algorithm version, category weights, grade and confidence thresholds, radii and scoring parameters. A backend caller can supply the same shape from `score_config`.
- Listing: Skia score ring, reasons for each sub-score, deep-dive link, explicit demo notice and disclaimer. Deep-dive shows effective weights, contributions, unavailable categories, confidence, calculation date and model version.
- City plans: status, type, distance, impact and approval date; a separate screen with selectable GeoJSON polygons on Apple / Google Maps. Plans are fictional and identified as `DEMO-*`.
- Amenities: eight surveyed categories, counts and nearest place. Traffic: peak congestion, noise, nearest bus / rail / light rail and highway distance. Distances are explicitly straight-line estimates.
- Market: six annual price observations, Victory Native gradient line and an expandable values view for accessibility. Static SVG preview on web. Demo history is interpolated, not a market time series.
- English / Hebrew copy, logical spacing, screen-reader labels, loading / missing-property / retry states. Native ring animates once per property per app session and respects Reduce Motion.

## Preview model

The product spec defines categories and weights, but not calibrated sub-score formulas. The initial formulas are deliberately labeled an **uncalibrated preview**. They must be reviewed against licensed, verified data before use for real buyer decisions.

| Category | Weight | Preview calculation |
|---|---:|---|
| Plans | 30% | Baseline plus strongest nearby plan, weighted by approval stage and distance; separate confirmed renewal bonus. Radius 1 km, or 800 m for planned transit. |
| Amenities | 20% | Average of eight categories, combining count saturation and nearest distance within 800 m. Requires a complete survey, including explicit zero-count categories. |
| Traffic | 15% | Nearest operational transit and highway proximity, plus lower congestion / noise. Planned transit never counts as an operational stop. |
| Market | 25% | Relative price per sqm (60%) and five-year change (40%), bounded by configured ranges. At least three comparable deals required. |
| Property | 10% | Building age, elevator, parking, safe room, balcony and storage; upper-floor walk-up penalty; old-building renewal bonus only with recorded eligibility. |

Each category is clamped to 0–100 and rounded; the total is the rounded weighted sum. Missing or invalid category inputs exclude the category and redistribute its weight. An empty plan survey is known absence, not missing data. With no usable, enabled categories the engine returns `undefined` instead of inventing a score. Confidence measures the original weight covered: all enabled weight = high, at least 60% = medium, otherwise low. It does not establish source reliability or predict returns.

The current model does not infer renewal eligibility from age or plan proximity, nor score unprovided supply, demand, condition or planned-commercial observations. Those inputs need provider contracts and model calibration in B3. Fictional context and the score use the same values; reasons are no longer chosen independently at random.

## Backend boundary

There is no Supabase foundation, schema, authentication or ingestion pipeline in this repository yet. This change does not deploy a server or claim to implement the B3 pipeline. B0–B2 must establish the shared-domain packaging strategy, property context schema and service access first. B3 can then read context / config, call `computeScore` with an injected calculation timestamp, persist the returned score, and forward the scored event as described in `backend-spec.md` §9.2. The app consumes the returned score; production screens must not recompute it from an app-bundled configuration.
